Rahzaan: AI Career Guidance Platform

Feb 2026 to Present

Deployed agentic career guidance platform for Pakistani secondary school students. A 24-node LangGraph pipeline at 3.7-second first-response latency, maintained through 592 automated behavioural tests.

Stack
Python, LangGraph, FastAPI, Flutter, Supabase
Proof
Case studywaqas01cp.github.ioLive appvercel.app

Primary architect and director. The hard part is reasoning truthfully about eligibility: multiple exam boards with different percentage conversions, five streams, regulatory gating by several councils with distinct minima, and merit rules that are often unpublished.

in depth: Rahzaan9 points
  1. Built the evaluation harness the platform is maintained through: five named personas and a ten-scenario curriculum matrix producing 60 per-turn traces, 19 behavioural probes using paired before-and-after measurement and single-criterion isolation to attribute cause, a separated run-and-analyse pipeline, and a 46-file behavioural test suite of 592 automated tests catching regressions before users hit them.
  2. Refuted my own diagnosis of why the system over-asserted. I assumed thin data caused it; measuring across five data-completeness levels showed the opposite, the thinnest persona was the most honest, declining outright rather than fabricating. The real trigger was internal signal divergence, the model inventing an affective bridge to reconcile conflicting academic and psychometric inputs, so the scarcity guard I had planned would have fixed nothing. Redirected the fix to the divergence path, then added a deterministic post-generation gate as backstop after establishing that negative directives carry a reliability ceiling.
  3. Architected a 24-node LangGraph pipeline: fan-out across 9 concurrent nodes, fan-in through a central dispatcher, then two further stages, with 52 typed state fields and concurrent-write reducers. Cut first-response latency from 20 to 25 seconds down to 3.7 seconds. Per-node model routing lets any node's LLM be swapped through environment config alone, with LangSmith tracing for per-turn execution, node latency, and token usage.
  4. Built a production FastAPI backend: 22 REST endpoints, LangGraph checkpoint persistence to PostgreSQL, SSE streaming with a parallel keepalive task that defeats the host's 30-second proxy timeout, JWT authentication with bcrypt, rate limiting, 11 Alembic migrations against live data, a deterministic refresh endpoint that regenerates recommendations with zero LLM calls, and a profile summary generator running six parallel LLM calls plus synthesis off the event loop. Automated a 15-day job-market pipeline mapping 14,595 job titles to canonical career fields via Gemini.
  5. Engineered two model-independent LLM guardrails: a 9-criterion reflection gate that applies surgical corrections before any response streams, including a check that blocks unfounded emotional or clinical claims about a user, and deterministic context stripping, built after finding the model ignores "do not include" instructions but cannot discuss data it never receives. Verified across two model versions, alongside three callable tool interfaces and PII handling kept as concerns separate from the agents themselves.
  6. Shipped a 29-route Flutter frontend: onboarding, six assessment flows, O/A Level grade conversion, live streaming chat, recommendation dashboard, and a profile hub. Riverpod state management and cold-start timeout handling. Web build deployed on Vercel (live), with a contract test on the frontend asserting the same merit-tier contract the backend enforces.
  7. Designed the recommendation engine: a 265-item session drawn from item banks of 1,409, sized so a student who reassesses is not asked the same questions twice, across seven construct-grounded psychometric instruments including an original one derived from work-adjustment theory, with MBTI rejected on published reliability evidence. Scored by a multi-dimensional model blending interest-profile geometry, measured capability, and deterministic tier validation with no LLM call. Fully bilingual: every instrument and the entire session exist in English and Roman Urdu, and the conversation follows whichever the student uses, including mixed script within a sentence.
  8. Ran the build through a two-tier development harness of my own design, now my default method for any system of size: an architecture conversation producing versioned specifications, an implementer working from them under a written rules file across five role-scoped instruction sets, and LangSmith traces pulled back through a fetch skill to close the loop. Recorded across 334 session records in four months with the model and reasoning tier attributed per session, 53 audit documents over six whole-system audit phases, and a status register tagging every claim live-verified or believed so that doubt stays pointed at the unverified set.
  9. Coordinated two contributors through written setup guides, versioned interface contracts and 17 dated change notices, against a governance document versioned to v2.27 carrying 80+ locked decisions, with rehearsal runs before every destructive data operation and a documentation toolchain generating both the architecture view and the dissertation itself from code.

Applied LLM Workflow Research

Sep to Dec 2025

Behavioural study of Gemini 2.5 Pro identifying reproducible failure modes in production LLM workflows.

Stack
Python, Streamlit
Proof
Live appstreamlit.app
in depth: Applied LLM Workflow Research3 points
  1. Identified and named three failure modes: Optimal Answer Trap (the model locks onto its first acceptable answer and resists valid redirection), Final Synthesis Bias (output collapses toward a synthesised endpoint regardless of instruction), and Conversational Gravity (accumulated context progressively narrows model behaviour), each reproduced through documented prompt sequences.
  2. Ran controlled experiments across temperature, top-p, and top-k sampling; 1M-token context stress tests; adversarial red-teaming with hallucination injection; and context-ordering trials showing a ~30% retrieval error rate when context follows rather than precedes the instruction.
  3. Shipped a 5-stage prompting protocol combining intent decomposition, strict output schemas, and adversarial self-critique, deployed as an interactive Streamlit application with a failure-mode comparison view and a prompt template playground.
